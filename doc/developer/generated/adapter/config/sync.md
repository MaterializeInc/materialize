# adapter::config::sync

Implements `system_parameter_sync`, the periodic task loop that pulls parameters from the `SystemParameterFrontend` (LaunchDarkly or file) and pushes modified values to the `SystemParameterBackend` (coordinator via `ALTER SYSTEM SET`).
The loop ticks at a configurable interval (skipping missed ticks) and lazily initializes the frontend client on the first tick to avoid blocking startup. When `enable_launchdarkly()` is false and the configured client is LaunchDarkly, the frontend is torn down and the loop skips until it is re-enabled.
After each environment-wide pull-and-push, `sync_scoped_params` reconciles per-cluster and per-replica scoped parameter overrides. It first checks `SystemParameterFrontend::has_scoped_desired_state` and skips the reconcile if the desired state is unknown (for example, when the config-sync file could not be read), to avoid pruning all overrides on a transient read failure. When the desired state is available, it fetches a catalog snapshot via `Client::catalog_snapshot_expensive` (a direct coordinator round-trip, since the sync loop is not session-bound), evaluates each live cluster and replica against LaunchDarkly, and pushes the desired sparse `ScopedParameters` to the coordinator via `Client::update_scoped_system_parameters`. The prune scope is restricted to the clusters and replicas present in the snapshot so that an object created between the snapshot and the apply is not wiped by this reconcile.
Once the frontend is initialized, it is shared with the coordinator via `Client::install_scoped_system_parameter_frontend` (as an `Arc`) so that create-cluster and create-replica paths can resolve a new object's scoped overrides synchronously within their own transaction, rather than waiting for the next tick.
`evaluate_scoped_parameters` (exported `pub(crate)`) partitions synced parameters by `ParameterScope` (`Replica` vs `Cluster`) using `iter_synced`, builds `ReplicaEvalContext` and `ClusterEvalContext` structs for each live object via private helpers `build_replica_eval_contexts` and `build_cluster_eval_contexts`, and delegates to `SystemParameterFrontend::pull_replica_overrides` and `pull_cluster_overrides` respectively. Either pass is skipped entirely when there are no parameters of that scope. Optional `cluster_filter` and `replica_filter` arguments restrict evaluation to a subset of objects for the create-time synchronous resolve path. An empty `replica_filter` short-circuits the per-cluster scan so the create-cluster path (which passes an empty replica set) avoids unnecessary work.
