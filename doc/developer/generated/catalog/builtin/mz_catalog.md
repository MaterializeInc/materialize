# catalog::builtin::mz_catalog

Defines all built-in catalog objects for the `mz_catalog` SQL schema.

This module exports 76 public items: types, tables, materialized views, views, sources, and indexes.

**Types** — Materialize-specific pseudo-types and their array forms: `TYPE_LIST`, `TYPE_MAP`, `TYPE_ANYCOMPATIBLELIST`, `TYPE_ANYCOMPATIBLEMAP`; unsigned integer types `TYPE_UINT2/4/8` and their arrays; `TYPE_MZ_TIMESTAMP`, `TYPE_MZ_TIMESTAMP_ARRAY`; `TYPE_MZ_ACL_ITEM`, `TYPE_MZ_ACL_ITEM_ARRAY`.

**Tables** — `BuiltinTable` statics covering type system metadata, operator and function definitions, column and type details, and cluster sizing information.

**Materialized views** — Core catalog entities backed by queries over `mz_internal.mz_catalog_raw`: `MZ_DATABASES`, `MZ_SCHEMAS`, `MZ_CONNECTIONS`, `MZ_SECRETS`, `MZ_TABLES`, `MZ_COLUMNS`, `MZ_VIEWS`, `MZ_SOURCES`, `MZ_SINKS`, `MZ_CLUSTERS`, `MZ_CLUSTER_REPLICAS`, `MZ_ROLES`, `MZ_ROLE_PARAMETERS`, `MZ_OBJECTS`, `MZ_ALL_OBJECTS`, `MZ_DEFAULT_PRIVILEGES`, `MZ_SYSTEM_PRIVILEGES`, `MZ_AUDIT_EVENTS`, `MZ_KAFKA_SOURCES`, `MZ_KAFKA_SINKS`, `MZ_ICEBERG_SINKS`, and others. `MZ_KAFKA_CONNECTIONS` is a `BuiltinMaterializedView` (OID constant `MV_MZ_KAFKA_CONNECTIONS_OID`) that reads `Item` rows from `mz_catalog_raw`, pulls broker addresses and the progress topic out of the persisted `create_sql` via `parse_connection_details`, and keeps only kafka connections. The default progress topic is reconstructed in SQL to match `KafkaConnection::progress_topic` in the storage types crate. `MZ_SSH_TUNNEL_CONNECTIONS` is a `BuiltinMaterializedView` (OID constant `MV_MZ_SSH_TUNNEL_CONNECTIONS_OID`) that derives SSH tunnel connection details (public keys) by parsing `create_sql` via `parse_connection_details`. `MZ_AWS_PRIVATELINK_CONNECTIONS` is a `BuiltinMaterializedView` (OID constant `MV_MZ_AWS_PRIVATELINK_CONNECTIONS_OID`) that reconstructs the principal ARN from the environment-context functions `mz_aws_account_id()` and `mz_aws_external_id_prefix()`; the ARN format mirrors `AwsPrincipalContext::to_principal_string`. It keeps a `WHERE principal IS NOT NULL` guard so no row is emitted when the AWS context is absent, matching the packer it replaces. `MZ_KAFKA_SOURCES` is a `BuiltinMaterializedView` (OID constant `MV_MZ_KAFKA_SOURCES_OID`) that derives Kafka source details (topic and computed group ID) by parsing the raw catalog create SQL via `mz_internal.parse_kafka_source_details`; the `group_id_prefix` column holds the full computed `group.id`, not just the user-supplied prefix. `MZ_KAFKA_SINKS` is a `BuiltinMaterializedView` (OID constant `MV_MZ_KAFKA_SINKS_OID`) that derives the Kafka sink topic by parsing `create_sql` via `mz_internal.parse_catalog_create_sql`. `MZ_ICEBERG_SINKS` is a `BuiltinMaterializedView` (OID constant `MV_MZ_ICEBERG_SINKS_OID`) that derives the Iceberg sink namespace and table name from `create_sql` via `mz_internal.parse_catalog_create_sql`. `MZ_SINKS` is a `BuiltinMaterializedView` (OID constant `MV_MZ_SINKS_OID`) that derives all sink metadata from the persisted `create_sql` via `mz_internal.parse_catalog_create_sql`; the `size` column is deprecated and always NULL. `MZ_AUDIT_EVENTS` is a `BuiltinMaterializedView` (OID constant `MV_MZ_AUDIT_EVENTS_OID`) whose `event_type` column covers `create`, `drop`, `alter`, `grant`, `revoke`, and `comment`, and whose `object_type` column covers `cluster`, `cluster-replica`, `connection`, `database`, `func`, `index`, `materialized-view`, `metric-sink`, `network-policy`, `role`, `secret`, `schema`, `sink`, `source`, `system`, `table`, `type`, `view`, and `continual-task`. `MZ_CLUSTERS` and `MZ_CLUSTER_REPLICAS` are `BuiltinMaterializedView` objects that derive cluster and replica metadata from the durable catalog raw source; `MZ_CLUSTER_REPLICAS` resolves the `disk` column via a LEFT JOIN against `mz_cluster_replica_size_internal` (which retains rows for disabled sizes), so replicas with unknown sizes return `NULL` for `disk` rather than causing an error. `MZ_DEFAULT_PRIVILEGES` decodes `DefaultPrivileges` rows from `mz_catalog_raw`, mapping the proto enum numeric `object_type` to its SQL display name via a CASE expression. `MZ_SYSTEM_PRIVILEGES` decodes `SystemPrivileges` rows and unnests them into `mz_aclitem` values. These carry `Ontology` annotations with entity names, descriptions, and `OntologyLink` relationships for the catalog graph. `MZ_INDEXES` is also a `BuiltinMaterializedView` but is generated dynamically via the `pub(super) make_mz_indexes` function rather than declared as a static, so it is not counted among the module's exported statics.

**Views** — Additional SQL views for derived catalog information such as `MZ_TIMEZONE_ABBREVIATIONS` and `MZ_TIMEZONE_NAMES`.

**Sources** — `BuiltinSource` items backed by `DataSourceDesc::Catalog` or `IntrospectionType`.

**Indexes** — `BuiltinIndex` constants for accelerating catalog queries: `MZ_DATABASES_IND`, `MZ_SCHEMAS_IND`, `MZ_CONNECTIONS_IND`, `MZ_TABLES_IND`, `MZ_TYPES_IND`, `MZ_OBJECTS_IND`, `MZ_COLUMNS_IND`, `MZ_SECRETS_IND`, `MZ_VIEWS_IND`, `MZ_CLUSTERS_IND`, `MZ_INDEXES_IND`, `MZ_ROLES_IND`, `MZ_SOURCES_IND`, `MZ_SINKS_IND`, `MZ_MATERIALIZED_VIEWS_IND`, `MZ_CLUSTER_REPLICAS_IND`, `MZ_CLUSTER_REPLICA_SIZES_IND`, `MZ_KAFKA_SOURCES_IND`, and more.
