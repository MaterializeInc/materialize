# persist::s3

Implements the `Blob` trait backed by Amazon S3, with support for STS role assumption, custom endpoints, and explicit credential overrides.
Large objects are uploaded with S3 multipart upload; downloads fetch parts concurrently using the S3 `part_number` parameter on GetObject requests, reusing the original upload boundaries without requiring stored metadata. When a store does not return the `x-amz-mp-parts-count` header, `get` falls back to byte-range requests: it reads the total object size from the `Content-Range` denominator of the first response, and if the first part is shorter than the total, fetches the remainder in chunks sized to the first part. A length check against the `Content-Range` total catches silent truncation and converts it to a retryable error regardless of whether the header is present.
`S3BlobConfig` is constructed asynchronously because SDK credential resolution may require network calls. Cloning `S3BlobConfig` shares the underlying `S3Client` and its HTTP connection pool; connection-pool isolation (as hedged gets require) needs a fresh `S3BlobConfig::new`.
Timeout behavior is driven by a `MetricsSleep` adapter that intercepts marker `Duration` values injected into the SDK's `TimeoutConfig` and substitutes live values from `BlobKnobs`, also incrementing per-timeout-type metrics counters.
Response body timeouts are not covered by the SDK's `TimeoutConfig`; a body that stops arriving is bounded by the SDK's built-in stalled-stream protection (enabled by default for downloads), not by the operation or attempt timeout.
