# storage-operators::persist_source

Provides the `persist_source` Timely operator that reads from a persist shard and emits rows and errors.
It wraps the lower-level `shard_source` from `mz_persist_client`, adding storage-specific logic for MFP pushdown, stats-based part filtering, and txn-wal integration.
`persist_source` is generic over both an error type `E` and a container builder `CB` for the ok-side output, allowing callers to choose the output container type for rows. `persist_source_core` and `decode_and_mfp` are generic over `E` (which must implement `From<DataflowError>` and `From<EvalError>` in addition to `timely::ExchangeData + Ord + Clone + Debug`).
Defines `Subtime`, an opaque sub-timestamp token that enables finer-grained frontier progress within a single timestamp, used for granular backpressure flow control.
`Subtime` implements `differential_dataflow::lattice::Lattice` (join as max, meet as min), `Maximum` (returning `u64::MAX`), and `columnation::Columnation` (using `CopyRegion<Subtime>`), allowing it to participate in differential dataflow lattice operations and columnar arrangements. It also derives `columnar::Columnar` so the refined `(Timestamp, Subtime)` time can be used in columnar containers.
`RowVecBuilder<T>` is a type alias for `ConsolidatingContainerBuilder<Vec<(Row, T, Diff)>>`, the default ok-side container builder used by callers that want consolidating row vectors.
The `persist_source_core` function handles a scoped inner dataflow, wiring up `fetch_parts` (which runs `shard_source` with optional backpressure) and `decode_and_mfp`. It returns a combined `StreamVec` of `Result<Row, E>` at the refined `(Timestamp, Subtime)` time for use by the upsert operator.
The `decode_and_mfp` operator processes `FetchedBlob` values from `fetch_parts`, lazily parsing them into `FetchedPart` via a `PendingPart` enum, and applies MFP logic. It yields fuel-bounded to preserve interactivity. Its inner processing loop audits parts selected for `filter_pushdown_audit`: for `SourceData(Ok(row))` rows, if the MFP produces output the part should not have been discarded; for `SourceData(Err(_))` rows, the mere presence of an error row is a pushdown violation since errors must surface regardless of any filter. Both cases log a Sentry-tagged error (redacting the MFP output and the error value to avoid leaking user data) and optionally panic when `STATS_AUDIT_PANIC` is set.
A `filter_pushdown_audit` proptest module in the `#[cfg(test)]` block provides end-to-end soundness checks for persist filter pushdown: it builds a part from actual rows, computes the real production column statistics, then asserts that `filter_result` never returns `FilterResult::Discard` for a part whose MFP produces output on some actual row. This exercises the full path from stats derivation through `col_stats` to the interpreter, catching both interpreter bugs and stats-derivation bugs. The module also includes targeted regression tests via `assert_part_kept`, which verifies that a specific predicate keeps a part when real rows match it; one such test covers the case where a float column's `PrimitiveStats` bounds are unordered (e.g., `-NaN` as the lower bound in arrow total order, which sorts above finite values in `OrderedFloat` order), ensuring those bounds are not misread as an empty range and incorrectly discarding the part.
